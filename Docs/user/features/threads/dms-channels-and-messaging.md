# DMs, Channels, Replies, Mentions, and Media

FlowState is not only for task planning. It also includes conversation spaces where work is discussed, clarified, handed off, and reviewed. This guide explains how messaging works so you can communicate clearly without getting lost in activity.

## The difference between boards and threads

Boards are structured planning spaces.

Threads and messages are conversational spaces.

A simple way to think about it:

- boards answer: what work exists and what state is it in
- messages answer: what are people saying, asking, deciding, or sharing right now

Some work begins in a message and later becomes a board card. Some work begins on a board and later needs discussion in a thread.

## The main kinds of communication spaces

FlowState usually gives you several ways to communicate:

- direct messages
- channels or shared conversations
- threaded replies
- mentions
- forwarded or shared message content depending on permissions and feature availability

## Direct messages

Direct messages are best for person-to-person or small private conversations.

Use a direct message when:

- you need to ask one person a focused question
- the topic does not belong in a wider team channel
- you are clarifying ownership or timing
- sensitive or narrow coordination is more appropriate than public discussion

Avoid overusing direct messages for work that the whole team needs to see. Private convenience can create team confusion if important decisions disappear into one-to-one conversations.

## Channels or shared conversations

Channels are for group communication. They help a team keep shared information visible instead of burying it in private conversations.

Channels are useful for:

- team updates
- ongoing project discussion
- requests for review
- public coordination
- sharing context that several people need

A good rule:

- if the answer will help several people, prefer a shared conversation
- if the answer only concerns one person, a direct message may be enough

## Message composer basics

The message composer is the input area where you type and send messages. Depending on the current screen, it may support:

- plain text
- multi-line writing
- mentions
- attachments or media
- reply mode
- forward or share actions

Take a second to confirm where your composer is pointing before sending. The same typed message means very different things if you are in:

- a DM
- a public channel
- a reply drawer
- a board comment field

## Replies and threaded discussion

Replies help keep conversation organized. Instead of dumping every related thought into the main stream, a reply lets you attach discussion to a specific message.

Use replies when:

- you are answering one particular message
- you want the surrounding timeline to stay readable
- you need to discuss one subtopic without interrupting everything else

Replies are especially helpful in busy channels because they reduce noise in the main message flow.

## Mentions

Mentions are used to call someone’s attention to a message.

Mention someone when:

- you need a response
- you are assigning follow-up
- you need approval or review
- you want to make sure a person sees the message

Do not mention people casually just to include them without purpose. Over-mentioning trains people to ignore mentions.

Useful mention patterns:

- ask a direct question
- assign a next step
- request review on a specific item
- notify the exact person who owns the decision

## Notifications and unread state

Unread indicators, badges, and counters help you know where attention may be needed.

They usually mean:

- there are messages you have not opened yet
- there are new mentions or updates since your last visit
- something in the current workspace changed

An unread badge does not always mean emergency. It means:

- there is new information

Prioritize unread items by:

- direct mentions first
- urgent team channels second
- general updates third

## Media and attachments in conversations

Some message areas support screenshots, images, or files. These are useful when words alone are not enough.

Common examples:

- showing a bug visually
- sharing a draft design
- providing a document for review
- attaching a file needed for the next step

Before sending media, think about:

- whether the channel is appropriate
- whether the file contains sensitive information
- whether the message should explain what the recipient is meant to notice

A screenshot with no explanation may be less useful than a screenshot plus one sentence that says what is wrong.

## Forwarding and sharing messages

If the interface offers forward or share actions, use them carefully.

Ask yourself:

- is it appropriate to move this message to another audience
- does the new audience have enough context
- could the message expose private information from the original conversation

Not every message belongs in every channel. Even when forwarding is available, judgment still matters.

## Long messages

Long messages are sometimes necessary, especially for status updates, incident notes, and detailed instructions. But long messages should still be readable.

Ways to make them easier to read:

- use short paragraphs
- separate steps clearly
- state the goal near the top
- mention the exact person only if you need action from them

If a message becomes a lasting reference document, it may belong in a board card, shared document, or formal guide instead of only in chat.

## Good communication habits in FlowState

### Keep the audience in mind

Write differently depending on where you are posting:

- DM: personal and focused
- channel: shared and useful to multiple people
- reply: attached to one specific point

### Ask for a specific outcome

Messages are easier to act on when they clearly ask for:

- a decision
- a review
- a confirmation
- a file
- a timeline

### Separate updates from decisions

An update says what happened.

A decision says what will now be done.

Mixing the two without clarity can create confusion later.

### Use boards when work becomes structured

If a chat topic turns into a real task, move it into a card or board process instead of letting it stay buried in conversation.

## Common mistakes

### Starting important work only in DMs

This makes shared visibility weaker.

### Posting too broadly

Not every channel needs every update.

### Writing vague messages

Messages like `Can someone do this?` are much weaker than `@Name can you review the mobile spacing issue by today?`

### Ignoring reply structure

When a busy channel becomes hard to follow, reply threads are often the solution.

### Sending screenshots without context

Always explain what the recipient should notice.

## If you cannot send a message

Possible reasons include:

- your session expired
- you lost access to that conversation
- your message exceeded a validation limit
- the server is temporarily unavailable
- your connection dropped

If the app shows a permission message, do not keep retrying blindly. Check whether you are still authorized to post there.

## When to choose each communication style

Choose a DM when:

- the topic is private or one-to-one

Choose a channel when:

- several people need visibility

Choose a reply when:

- you are continuing one exact message thread

Choose a board comment or card update when:

- the conversation belongs to a specific piece of tracked work
