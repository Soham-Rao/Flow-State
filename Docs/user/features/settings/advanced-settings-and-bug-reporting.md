# Advanced Settings and Bug Reporting

Advanced settings contain lower-frequency operational tools that are still important when something goes wrong or needs follow-up.

## Current main purpose

The main advanced workflow today is the in-app bug report system.

This exists so that:

- users can report bugs without waiting for full SMTP support flows
- admins can triage issues inside FlowState

## What regular users can do

Regular signed-in users can:

- open the bug report form
- send a report
- see their own recent reports
- follow status changes on those reports

## What admins can do

Admins can additionally:

- review the full bug inbox
- filter reports
- mark reports as open, triaged, or closed

This keeps the workflow useful without making every user responsible for internal triage.

## Writing helpful bug reports

A helpful bug report should explain:

- where you were
- what you clicked or tried
- what happened
- what you expected instead
- whether it happens every time

The more reproducible the report is, the more likely it is to be fixed quickly.

## What this page is not

This is not yet a full support center with:

- email delivery
- attachments
- threaded support conversation
- public GitHub issue creation

Those are future-phase concerns. The current system is intentionally lightweight.
