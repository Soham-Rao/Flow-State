# Workspace Settings and Admin Pages

Workspace settings are different from personal settings because they can affect many users, not just you.

## Typical workspace-level concerns

Depending on your permissions, these areas may include:

- role management
- permission changes
- role assignment
- workspace-wide rules or controls
- appearance preferences
- thread badge or counter behavior

## Personal controls that can still appear on the general page

The general settings page is not only for admins. It may also include personal client preferences such as:

- theme selection
- font selection
- spacing selection
- thread counter or badge mode

This can feel slightly surprising at first because the same page may mix:

- personal experience settings
- shared workspace administration

So always read the section title before assuming a change affects everyone.

### Theme

Theme options commonly include:

- light
- dark
- system

These change how the interface looks for you.

### Typography

Typography settings change the reading style of the client. They affect the font family, not the underlying data.

### Spacing

Spacing controls change how dense or airy the interface feels. Some users prefer more information on screen at once, while others prefer more visual breathing room.

### Thread counters

Thread badge settings can usually control whether the app surfaces:

- all unread thread counts
- mention-only counts
- no badges at all

This is a visibility preference, not a permission.

## Why this area deserves caution

A mistake in workspace settings can:

- block users
- expose users to things they should not see
- create confusion about who can do what

That is why these settings are usually admin-restricted or partially restricted.

## Before changing anything here

Ask:

- am I changing my own preferences or a team-wide rule
- who else will be affected
- is there an override already handling this case
- should this be a role change or a narrower exception

If the answer is unclear, slow down before confirming the action.

## Role management as separate workflows

If your permissions allow role administration, the page may expose separate actions for:

- creating roles
- managing existing roles
- assigning roles to users

These are separate because they answer different questions:

- what roles exist
- what each role can do
- who has which roles right now
